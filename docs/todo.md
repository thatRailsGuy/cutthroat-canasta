## Server and project

- [ ] Send only the new feed events. Every broadcast resends the whole round's feed, so the data sent grows with the square of the round length. Watch it; if it matters, only [gameState.ts](../apps/web/src/gameState.ts) on the client would need to change.
- [ ] Add bots: computer players that take a seat and play their own turns. They would fill a table when there aren't enough people, and let `/dev` play a game forward instead of leaving its seats idle (today the [dev index](../apps/web/src/dev/DevIndexPage.tsx) only holds made-up seats online). A bot sees only its own `PlayerView` ([view.ts](../packages/engine/src/view.ts)), the same as a player, and sends ordinary actions, so the server checks its moves like anyone else's (`applyAction`, [actions.ts](../packages/engine/src/actions.ts); `legalityPreview`, [preview.ts](../packages/engine/src/preview.ts), can test a move before sending it). **Open questions:** where a bot runs (in the room's Durable Object, so it keeps playing with no tab open, or in a browser tab, which is enough for `/dev`); how well it plays (legal moves at random, or simple rules for drawing, picking up the pile, melding and discards); whether players can add one from the lobby, and how it shows at the table; and whether a bot can take over the seat of a player who quit or went away. Showing bots to players needs a mockup.
- [ ] Let a player stand in for an away host in the lobby. The server already lets anyone start the game while the host is away, and makes them host (`start`, [room.ts](../apps/server/src/room.ts)). But the lobby ([Lobby.tsx](../apps/web/src/pages/Lobby.tsx)) shows **Start game** only to the host, and other players see "Waiting for the host to start.", so a lobby whose host went away still can't start. A stand-in needs a Start button there. Kick and listing the table stay host-only. Needs a mockup.
- [ ] Give the public table list the same grace as standing in. A listed room drops off the list the moment its host disconnects ([tables.ts](../apps/server/src/tables.ts)), so a host whose phone sleeps for a second loses the listing. After PR #2 it could use `hostAway` and `HOST_AWAY_AFTER_MS`.
- [ ] Share `hostAway` between the server and the client. Lint allows only type imports from the server, so after PR #2 the client keeps a typed copy in `apps/web/src/away.ts`, and its three-line body must be kept in step with [protocol.ts](../apps/server/src/protocol.ts) by hand. A small shared package under `packages/` would hold the one copy.
- [ ] Say which request a server error answers. Errors arrive as toasts with no request id, so after PR #5 the host drawer ([HostDrawer.tsx](../apps/web/src/components/HostDrawer.tsx)) assumes any error while a rejoin link is pending is its refusal. That holds while the drawer is modal and the server answers in order. Echoing a request id in `error` would make it certain.
- [ ] Decide which round a rejoin-link notice belongs to. After PR #2, a link the host makes at the end of a round has no state message after it, so its notice stays into the next round instead of being cleared ([gameState.ts](../apps/web/src/gameState.ts)).
