## Server and project

- [ ] Send only the new feed events. Every broadcast resends the whole round's feed, so the data sent grows with the square of the round length. Watch it; if it matters, only [gameState.ts](../apps/web/src/gameState.ts) on the client would need to change.
- [ ] Add bots: computer players that take a seat and play their own turns. They would fill a table when there aren't enough people, and let `/dev` play a game forward instead of leaving its seats idle (today the [dev index](../apps/web/src/dev/DevIndexPage.tsx) only holds made-up seats online). A bot sees only its own `PlayerView` ([view.ts](../packages/engine/src/view.ts)), the same as a player, and sends ordinary actions, so the server checks its moves like anyone else's (`applyAction`, [actions.ts](../packages/engine/src/actions.ts); `legalityPreview`, [preview.ts](../packages/engine/src/preview.ts), can test a move before sending it). **Decided (2026-10-14):** a bot runs in the room's Durable Object, so it keeps playing with no tab open, with a short pause between its moves (an alarm) so people can follow them. It plays by simple rules: draw from the stock unless picking up the pile is legal and worth it, meld once it has the minimum, build toward canastas, discard what is least use to it and to the next player, and go out when it can. The host adds a bot from the lobby with **Add a bot**, and can remove it again. That can't be **Kick** as it is: a kick adds the player to `state.kicked`, and the lobby then offers **Let back in** for them (`removeSeat`, [room.ts](../apps/server/src/room.ts)). So a bot needs its own remove action, or kick needs a special case for bots. A bot has a name and a bot badge on its seat, so nobody takes it for a person, and its moves show in Table talk like anyone else's. A bot must never become host. When the host goes, `removeSeat` and `nextHost` give the host role to the next seat, so both must skip bots. A bot has no socket, so it is never in `connected`, and `hostAway`, `takeOver` and the away dot would all treat it as away. The first bot work must settle how a bot counts as present. **Still open:** how bots are named, whether a table has a limit on bots, and how bots count toward the seat limits. A table holds at most `MAX_PLAYERS` (8) ([game.ts](../packages/engine/src/game.ts)), so bots that fill it leave no seat for a person to join. And do bots count toward the `MIN_PLAYERS` (2) needed to start? The lobby button and the badge need a mockup.

That holds while the drawer is modal and the server answers in order. Echoing a request id in `error` would make it certain.
